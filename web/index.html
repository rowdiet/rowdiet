rowdietPostgres column-tetris, statically

Paste migration DDL. Postgres pads every row so each column starts on its type's alignment boundary — a bad column order wastes those bytes on every row, and it is only free to fix before the migration is applied. This page runs the real PostgreSQL 17 parser compiled to WebAssembly; nothing leaves your browser.

Fixed-width columns are byte-exact from DDL alone; varlena columns (text, jsonb, numeric, …) are shown in the long-form scenario with payloads excluded — estimates, never guarantees. Suggested order: alignment descending, irregular sizes at group ends, varlena last.
